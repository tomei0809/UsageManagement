# UsageManagement

GitHub Actions、Cloudflare、AWS S3、Supabase、Vercel、Claude、OpenAI、Google Drive など、**複数のサービスの無料枠と利用量を 1 画面で確認・管理する**ための個人向け Web アプリです。

---

## 概要

### 背景

個人開発では、ホスティング・DB・CI・AI API など多くのサービスを無料枠の中で使います。ところが上限・単位・リセット日・確認方法はサービスごとにばらばらで、状況を知るには管理画面を一つずつ開くしかありません。気づいたときには上限に達していた、無料期間が終わっていた、ということが起こりがちです。

このアプリは使用量を一か所に集め、上限に近づく前に気づけるようにします。サービスごとの違いは、**サービスに依存しない共通のデータモデル(指標単位)**と、**サービス別の取得処理(コレクター)**を差し替える方式で吸収しています。

### システム構成図

```
ブラウザ ──HTTPS──▶ Cloudflare Access ──▶ Worker (Hono)
                                            ├─ /api/*      CRUD・手動入力・ダッシュボード集計
                                            ├─ 静的ファイル  React SPA
                                            └─ scheduled()  Cron(6時間ごと)→ 停止判定 → コレクター
                                                              ├─ GitHub / Cloudflare / OpenAI / Google / AWS の公式 API
                                                              └─ Discord Webhook(通知)
                                         D1 (SQLite)   services / metrics / snapshots / collector_runs / credentials(暗号化)
                                         Secrets       暗号化マスターキー
```

### 技術構成

| 層 | 技術 | 選んだ理由 |
|---|---|---|
| ホスティング / API | Cloudflare Workers + [Hono](https://hono.dev/) | 常時起動のサーバーが不要で、Free プランで動く。定期実行(Cron Triggers)・秘密情報(Secrets)・DB を同じアカウントで扱える |
| データベース | Cloudflare D1(SQLite)+ Drizzle ORM | このアプリのデータ量は Free の容量・書き込み回数に対して十分に小さい。スキーマから型を作れる |
| フロントエンド | React + Vite(SPA)、Workers Static Assets で配信 | 管理画面には SSR も SEO も不要。SPA にすると Worker の CPU 使用も少なく済む |
| グラフ | Recharts(詳細画面でのみ遅延読み込み) | 棒・折れ線・基準線・ツールチップがそろっている。ダッシュボードの初期表示には含めない |
| アクセス保護 | Cloudflare Access(Zero Trust) | ログイン処理を自作しなくてよい。Worker 側でも JWT を検証する |
| テスト | Vitest | 使用率・リセット日の計算を純粋関数にしてテスト |
| 言語 | TypeScript | 計算ロジックと型を Worker と画面で共有 |

### 運用状況

Cloudflare 上で運用中です。実アカウントで動作を確認済みなのは **GitHub Actions・AWS S3 の自動取得、Discord 通知、Cloudflare Access によるログイン保護**です。Cloudflare Workers・OpenAI・Google Drive のコレクターは模擬応答でのテストのみです([docs/services.md](docs/services.md) の「検証ログ」)。

## 業務要件

- 利用している複数サービスの無料枠と使用量を、**1 画面で**把握できること。
- 上限に**近づいたとき・期末までに超えそうなとき**に、画面を見に行かなくても気づけること(通知)。
- 無料期間の終了など、**期限のある無料枠**を見落とさないこと。
- 公式 API で取得できないサービスも、**手動入力で同じ画面に**載せられること。
- 運用費は原則 0 円で、常時起動のサーバーを持たないこと。利用者は自分 1 人。
- 無料枠の内容は頻繁に変わるため、**上限値をアプリに固定せず**、利用者が公式ページを見て入力・変更できること。

## 機能要件

### サービスと指標の管理
- サービスの登録・編集・削除。1 つのサービスに複数の指標を持てる(例:Supabase の「DB 容量」と「Egress」)。
- 指標ごとに次を設定できる:単位、上限(空欄なら上限なし)、種類(期間内の累積 / その時点の量)、リセット方式(毎月 指定日 / 毎日 / 毎週 指定曜日 / 直近 N 時間のローリング / なし)、リセット基準のタイムゾーン、注意・警告の閾値、「古いデータ」とみなす時間。
- 無料期間の終了日をサービスごとに登録でき、残り日数を表示する。

### 使用量の記録
値は取得方法を区別して保存・表示する。

| 区分 | 意味 |
|---|---|
| **API取得** | 公式 API から自動取得した値 |
| **手動入力** | 管理画面などを見て利用者が入力した値(確認日時とメモも残せる) |
| **推定値** | 履歴などから推定した値 |

入力・取得のたびに履歴として保存する。自動取得した値は削除できない(手動入力のみ削除可)。

### ダッシュボード
- 指標ごとに使用率の横棒グラフ、使用量 / 上限、残り、次回リセット日と「あと N 日」、最終更新日時、取得方法、古いデータの表示。
- **警告レベル**:既定は 80% で注意、95% で警告、100% で上限到達。閾値は指標ごとに変更できる。レベルは色だけでなく文字でも示す。
- 深刻な状態のサービスほど上に並べ、上限到達・警告・注意・古いデータ・取得失敗の件数を表示する。
- **要対応リスト**:注意以上の指標と超過見込みの指標を、深刻度順に上部へまとめる。
- **今期の料金**:単位が USD の指標を合計し、上限を予算として使用率・予測を出す。

### 履歴グラフ
- サービス詳細画面で 30 日 / 90 日の日別、12 か月の月別を表示する。
- 累積型の指標は「日別の使用量」と「当期の累計」を別々のグラフにし、上限線とリセット日を重ねる。「その時点の量」の指標は記録値の推移を表示する。
- 月別は、毎月 N 日にリセットする指標ならリセット期間ごと(例:15 日〜翌 14 日)、それ以外は暦月で集計する。日次リセットの指標は各日の使用量を月ごとに合計する。
- すべてのグラフは表に切り替えられる。

### 自動取得
Cron で 6 時間ごとに公式 API から取得する。取得方法を選んで認証情報を入力すると、対応する指標が作られる。

| サービス | 取得する値 | 必要な認証 |
|---|---|---|
| GitHub Actions | 当月の Actions 使用分数、超過料金(USD)。当月の過去分を 1 日ずつ補完することもできる | Fine-grained トークン(Plan: Read-only) |
| Cloudflare Workers | 当日(UTC)のリクエスト数(アカウント全体) | API トークン(Account Analytics: Read) |
| OpenAI API | 当月の利用料金(USD)。プリペイド残高は手動 | Admin キー |
| Google Drive | 使用容量(上限も自動で反映) | OAuth 2.0 |
| AWS S3 | バケットの使用容量・オブジェクト数(CloudWatch、1 日 1 回更新)。リクエスト数・料金は手動 | IAM アクセスキー(`cloudwatch:GetMetricStatistics` のみ) |
| Supabase / Vercel / Claude | 手動入力(Supabase・Vercel は将来の自動取得候補) | — |

- 「今すぐ取得」ボタンと取得履歴(成功・失敗とエラー内容)。
- **失敗時の扱い**:一時的なエラー(429 / 5xx / 通信エラー)はその場で 2 回まで再試行する。それでも失敗したら次の再試行までの間隔を 6 → 12 → 24 → 48 時間と延ばし、連続 N 回(既定 5 回)失敗したらそのサービスの定期取得を自動停止する。

### 定期チェックの停止・再開
上の範囲で止めると、下の範囲は実行されない。

| 範囲 | 操作する場所 | 内容 |
|---|---|---|
| アプリ全体 | 設定 → 定期取得「すべて停止」 | すべてのサービスの定期取得を止める |
| サービス | サービス詳細 → 自動取得 | 「停止」(無期限)、「一時停止 1日 / 7日 / 30日」(期限が来たら自動で再開)、「再開」 |
| 指標 | サービス詳細 → 各指標の「この指標を自動取得する」 | その指標だけ値を保存しない。すべての指標をオフにすると API 自体を呼ばない |
| 通知 | 設定 → Discord 通知「停止」 | 通知だけを止める(取得は続く) |
| 無料期間の終了 | サービスの編集 →「無料期間が終わったら自動取得を止める」 | 終了日を過ぎた最初の定期実行で自動停止 |

- 連続失敗による自動停止の回数は設定で変更できる(0 で無効)。停止理由は画面に表示する。
- 停止中でも「今すぐ取得」と手動入力は使える。停止・再開の操作はログに記録する。

### 超過予測
- 直近 7 日のペース(期間開始から 7 日未満なら期間開始からのペース)で、期末の使用量と上限に達する日を予測する。「その時点の量」の指標は、上限に達する日を 90 日先まで予測する。
- 予測は保存せず表示のたびに計算し、「予測」ラベルと破線で**実測と区別**する。

### 通知(Discord)
- 使用率が 注意 → 警告 → 上限到達 と**上がったときだけ**通知する。ほかに、初めて超過見込みになったとき、無料期間の終了 30 日前・7 日前・終了時、自動取得が自動停止したときに通知する。
- 同じ期間内で同じ通知は繰り返さない。

## 非機能要件

### コスト
- Cloudflare の Free プランの範囲で動く。データ量は 10 年使っても D1 Free の容量上限を大きく下回り、書き込み回数も Free の 1 日上限の 1% 未満に収まる。
- 課金が発生する API(AWS の `GetMetricData`、Cost Explorer など)は使わない。

### セキュリティ
- アプリ全体を Cloudflare Access で保護する。Worker も `Cf-Access-Jwt-Assertion` を検証し、Access を通らない直接アクセスは拒否する。設定がないときは拒否する(fail closed)。
- 自動取得に使う API トークンは **AES-256-GCM で暗号化して保存**する。暗号化鍵は Workers Secret に置き、コード・Git・DB には入れない。
- 保存したトークンは API からも画面からも読み出せない(末尾 4 文字のヒントのみ表示)。変更は上書きで行う。
- 取得エラーのメッセージには、応答本文の先頭 160 文字までしか残さない。
- トークンは各サービスで読み取り専用かつ最小のスコープで発行する前提とする。

### 可用性・耐障害性
- 常時起動のサーバーを持たず、Cron で定期実行する。
- あるサービスの取得失敗が他のサービスに影響しない(サービスごとに再試行・停止を管理する)。

### 保守性・拡張性
- 管理の単位はサービスではなく**指標**。上限・単位・リセット方式を指標に持たせ、特定のサービスに依存しない。
- サービスの追加・API 仕様の変更は、コレクター(1 サービス 1 ファイル)の追加・修正で済む。
- 使用率・リセット期間・集計・予測・停止判定は純粋関数にし、単体テストで検証する。

### データの扱い
- 時刻は UTC(ISO 8601)で保存し、日付の区切りは指標ごとのタイムゾーンで計算する。
- 予測値は保存しない。保存するのは取得・入力した値だけで、取得方法も記録する。
- 履歴グラフや予測の元になるため、自動取得した値は削除できない。
